# 5 分钟演示与讲解

先完成一遍真实操作，再按自己的理解讲。项目初版为 AI 辅助实现；下面是讲解提纲，不是已经完成的个人贡献声明。

## 演示顺序

1. **0:00–0:40 问题**：传统 CMDB 查询需要记字段与筛选条件。这个学习项目把“找设备并稽核”的任务拆成受约束的工具调用，并保留依据。说明全部是合成数据。
2. **0:40–1:40 主流程**：输入“查询 A01 机柜的设备，并检查数据异常”。展示 3 条资产、缺少负责人和非法 IPv4 两个问题。右侧依次查看 `list_assets`、`audit_assets` 的参数和返回值。
3. **1:40–2:20 边界**：输入“删除 SYN-001”，说明没有写工具；输入“查询 Z99 机柜的资产”，说明没有编造记录；查看 SYN-003 详情，证明表格与原字段对应。
4. **2:20–3:10 可追踪**：展开 JSON，解释 trace_id、sequence 和 start/tool/final/error。下载记录；资产台账过滤 B02 + dev，应只剩 SYN-006。
5. **3:10–4:00 评测**：打开评测结果。20 条固定样例检查资产 ID、异常、工具链和澄清 / 拒绝文本。20/20 是确定性路由回归，不是大模型准确率。
6. **4:00–5:00 设计取舍**：打开源码说明运行时预算、工具参数校验、模型适配器、前端 SSE 解析。坦诚说明真实模型尚未推理验收，下一步用相同资产断言测试真实模型并记录失败样例。

## 常见追问

**这算不算 Agent？**

架构有模型 / 规划器、工具选择、执行反馈和有预算的循环。默认演示中的规划器是规则替身，验证 Agent 工程链路；只有配置支持工具调用的真实模型后才执行模型驱动的循环。不能把规则演示说成真实大模型智能。

**为什么 SSE？**

服务端按事件发送过程，浏览器能逐步看到工具和结果。这里使用 fetch + ReadableStream 而非 EventSource，因为问题通过 POST JSON 提交。并未声称模型 token 级流式输出；模型适配器调用 stream=false，流的是执行事件。

**怎么防止误操作或幻觉？**

三个工具仅能读取合成 JSON；不提供 SQL、Shell、任意 URL 或修改工具。运行时检查参数和调用预算。结构化表格只取工具数据；模型自然语言仍可能出错。只读和事实正确性是两个不同问题，关键词拒绝并不等于完整提示注入防护。

**为什么不用 LangChain / FastAPI？**

初版通过标准库展示协议、消息历史、工具执行和失败边界，减少启动依赖。真实生产系统需要 ASGI、鉴权、请求取消、可观测性和数据适配，不应直接扩展这个本地 HTTP 演示来承担企业流量。

**哪些是你自己做的？**

按 [贡献记录](CONTRIBUTIONS.md) 的事实回答。初版代码和验证由 AI 辅助完成；个人后续的运行、代码阅读、修改、测试应有自己的提交与结果。没有完成前不要声称独立设计或优化。
